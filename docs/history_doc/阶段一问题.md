# 阶段一问题

目前项目中的“阿尔茨海默病知识普及、健康咨询助手”已经形成完整的前后端问答链路，但它本质上是一个“关键词分类 + 固定医学知识模板”的规则式助手，尚未接入大语言模型或知识库检索系统。

```text
用户输入问题
    ↓
前端 POST /assistant/chat
    ↓
后端关键词识别与意图分类
    ↓
选择预设科普答案
    ↓
返回答案 + 行动建议 + 医疗声明 + 权威来源
    ↓
前端渲染为聊天消息
```

### 1. 用户咨询入口

前端提供“科普助手”聊天页面，包括：

- 自由输入问题，最长500字。
- “总忘事怎么办”“语音筛查靠谱吗”等快捷问题。
- 大字号切换，方便老年用户。
- 页面顶部固定显示医疗边界和急症提醒。

主要页面代码在 [index.html](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/frontend/index.html:19)。

用户发送问题后，[app.js](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/frontend/app.js:115) 会调用：

```http
POST /assistant/chat
Content-Type: application/json

{
  "message": "最近总忘事，是阿尔茨海默病吗？"
}
```

收到结果后，前端会展示标题、科普回答、行动建议、医疗免责声明和权威资料链接。

### 2. 后端咨询接口

接口位于 [AssistantController.java](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/backend/src/main/java/com/alz/controller/AssistantController.java:19)，目前提供三个公开接口：

- `POST /assistant/chat`：健康咨询问答。
- `GET /assistant/topics`：查询支持的咨询主题。
- `GET /assistant/screening-guide`：获取语音采集、隐私和急症处理指引。

这些接口不要求登录，[JwtAuthenticationFilter.java](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/backend/src/main/java/com/alz/config/JwtAuthenticationFilter.java:49) 会放行所有 `/assistant/` 请求。

### 3. 问题是怎样被“理解”的

核心逻辑在 [AssistantServiceImpl.java](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/backend/src/main/java/com/alz/service/impl/AssistantServiceImpl.java:35)。

程序先将问题转为小写、删除空白，然后按优先顺序匹配关键词：

| 咨询类别 | 关键词示例 | 返回内容 |
|---|---|---|
| 急症信号 | 突然说不清、一侧无力、口角歪斜 | 提示立即拨打120 |
| 语音筛查 | 语音、录音、准确率、筛查 | 解释筛查能力和局限 |
| 就医诊断 | 确诊、医院、挂什么科、检查 | 说明诊断流程和建议科室 |
| 常见表现 | 忘事、记忆、迷路、找不到词 | 区分正常遗忘和需关注变化 |
| 风险管理 | 运动、饮食、睡眠、血压 | 提供可干预风险建议 |
| 家庭照护 | 家属、走失、沟通、护理 | 提供照护和沟通建议 |
| 治疗常识 | 药物、治疗、治愈 | 强调个体化评估和用药安全 |
| 默认回答 | 未匹配以上主题 | 介绍助手支持的咨询范围 |

因此，例如“最近总忘事，是阿尔茨海默病吗？”会被识别为 `symptoms`；“语音筛查可以确诊吗？”会被识别为 `speech_screening`。

### 4. 返回的是结构化健康建议

后端通过 [AssistantChatResponse.java](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/backend/src/main/java/com/alz/dto/AssistantChatResponse.java:5) 返回：

```json
{
  "intent": "symptoms",
  "title": "哪些变化值得关注",
  "answer": "……",
  "actionSuggestions": [
    "记录变化出现的时间和频率",
    "比较其与本人过去能力的差异",

  ],

    {
      "title": "美国国家老龄研究所：阿尔茨海默病的常见表现",
      "url": "https://..."
    }
  ],
  "urgent": false
}
```

科普来源目前硬编码为国家卫生健康委、美国国家老龄研究所和世界卫生组织等资料。

### 5. 医疗安全设计

当前实现包含几层安全边界：

- 所有普通回答都附带“不能诊断、排除或治疗”的声明。
- 优先识别疑似卒中表现，直接建议拨打120。
- 不推荐用户自行购药、停药或调整剂量。
- 筛查指引强调知情同意、敏感健康信息保护和停止筛查条件。
- 空问题会返回 HTTP 400。

相关行为已有单元测试覆盖，例如急症识别、语音筛查边界、空问题校验和隐私提示，见 [AssistantServiceImplTest.java](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/backend/src/test/java/com/alz/service/AssistantServiceImplTest.java:17)。

### 当前实现的主要局限

这个版本适合作为安全、可控的MVP科普助手，但还不算真正具备自然语言理解能力的“智能问诊助手”：

- 不能理解关键词之外的同义表达或复杂问题。
- 每次咨询相互独立，没有多轮对话上下文。
- 回答内容全部写在Java代码中，更新知识需要修改代码。
- 没有接入经过审核的医学知识库、RAG检索或大模型。
- 没有个性化分析用户年龄、病史、用药和筛查记录。
- 虽然后端返回了 `urgent` 字段，但前端尚未将急症回答显示成明显的红色警告。
- `/assistant/topics` 和 `/assistant/screening-guide` 已实现，但当前咨询页面尚未主动调用并展示它们。
- 运行时由 Spring Boot 实际提供的是 [backend/static](/C:/Users/Administrator/IdeaProjects/alz-backendalz-backend/alzheimers-voice-assistant/backend/src/main/resources/static/index.html) 中的页面；根目录 `frontend` 目前只是相同副本，后续需要建立同步或独立构建流程。
