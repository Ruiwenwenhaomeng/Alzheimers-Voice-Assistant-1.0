# PDF 文档与论文知识库接入方案

## 1. 总体思路

不建议直接把 PDF 文本追加到现有 `ad-faq.json`。更合适的方式是保留“标准 FAQ”和“论文/PDF 文档库”两条独立知识链路，在检索阶段合并、去重和重排结果。

```text
用户问题
  ├─ FAQ 检索：人工整理的标准问答
  └─ PDF 检索：论文、指南、政策和科普文件切片
          ↓
      合并、去重、重排
          ↓
  生成回答，并标明文件名、章节和页码
```

这样可以保留 FAQ 的稳定性和高置信度，同时利用论文和指南补充更细致、更新频率更高的知识。

## 2. PDF 入库流程

### 2.1 文件登记

保存原始 PDF，并为每个文件维护元数据：

- 文档 ID；
- 标题、作者和发布机构；
- 发布年份和版本；
- 文件类型，例如指南、论文、政策或科普资料；
- 权威级别；
- 适用地区；
- 原始来源网址；
- SHA-256；
- 版权和使用范围；
- 审核状态及审核人员。

文件哈希用于识别重复文件和版本变化，稳定的文档 ID 用于删除、更新和引用。

### 2.2 文本提取

普通文本型 PDF 可以使用 PyMuPDF 等工具提取文本；扫描版 PDF 应自动进入 OCR 流程。提取过程中需要保留：

- 页码；
- 标题和章节层级；
- 段落边界；
- 表格标题、内容和脚注；
- 图片说明；
- 参考文献边界。

不能只把整篇论文提取为一段无结构文本，否则难以精确检索和展示引用。

### 2.3 文档分块

中文资料初期可以采用以下参数作为评测起点：

- 每个切片约 400～800 个汉字；
- 相邻切片重叠约 80～120 字；
- 优先按章节、标题和自然段切分；
- 表格、结论、药物警告和诊疗建议不能从中间切断；
- 每个切片保留所属文档、章节和页码范围。

切片大小不应直接视为固定生产参数，需要根据实际召回评测调整。

### 2.4 向量化和入库

可以复用项目现有的 BGE-M3 Embedding 服务，批量生成向量并写入 Qdrant。

建议为 PDF 文档使用独立集合，例如：

```text
ad_faq_v1
ad_documents_v1
```

FAQ 和 PDF 文档生命周期不同，使用独立集合便于单独重建、扩容、回滚和调整检索参数。

每个 Qdrant 切片至少应保存以下 payload：

```json
{
  "documentId": "who-dementia-2026",
  "title": "Dementia fact sheet",
  "sourceType": "guideline",
  "pageStart": 4,
  "pageEnd": 4,
  "section": "Risk factors and prevention",
  "publishedAt": "2026-07-03",
  "fileHash": "...",
  "chunkIndex": 12,
  "authorityLevel": 5,
  "reviewStatus": "APPROVED",
  "knowledgeVersion": "2026.08.1",
  "sourceUrl": "..."
}
```

## 3. 检索策略

推荐同时查询 FAQ 和 PDF 文档库：

1. FAQ 检索返回前 2～3 条高置信度标准问答；
2. PDF 向量检索初步返回 15～30 个候选切片；
3. 按审核状态、适用地区、发布日期和权威级别过滤；
4. 使用重排模型选出最终 4～6 个切片；
5. 限制同一篇论文占据过多结果；
6. 合并语义重复内容；
7. 再将最终证据交给大模型生成回答。

如果同一问题同时命中指南、官方资料和普通研究论文，应优先使用指南与官方来源，同时把论文作为补充证据。

向量数据库即使没有正确答案，也通常会返回距离最近的内容，因此必须设置置信度阈值。低于阈值时应返回“知识库暂无充分证据”、进入受控联网检索或建议用户咨询专业人员，不能强行生成答案。

## 4. 引用和前端展示

回答来源应精确到文件、章节和页码，而不只是显示文件名。例如：

> 《中国阿尔茨海默病诊疗指南》，第 18 页，“诊断评估”章节。

前端可以提供：

- 来源标题；
- 发布机构和年份；
- 页码及章节；
- 原始来源链接；
- 在具备访问权限时打开对应 PDF 页面的链接。

大模型生成的每项医学结论都应能够映射到一个或多个检索切片。无法被证据支持的结论应删除或改为明确的不确定表达。

## 5. 增量更新和版本管理

建议用以下信息生成确定性切片 ID：

```text
SHA-256(documentId + fileHash + page + section + chunkIndex)
```

这样可以保证：

- 重复运行不会重复入库；
- 新版本文件能够被准确识别；
- 可以按文档删除全部旧切片；
- 索引失败后可以安全重试；
- 引用可以稳定定位到原始内容。

同一论文或指南出现新版本时，应先构建新的知识版本并完成离线评测，再通过 Qdrant collection alias 切换生产索引。旧版本保留一段时间用于快速回滚，不应让新旧版本长期混合检索。

## 6. 质量、安全和版权

### 6.1 文档质量检查

入库前至少检查：

- PDF 是否缺页或加密；
- OCR 是否出现大面积乱码；
- 页码映射是否正确；
- 标题层级是否丢失；
- 表格是否被错误拆分；
- 是否把整段参考文献作为医学结论入库；
- 文档是否属于最新有效版本；
- 是否存在重复文件或重复切片。

### 6.2 Prompt Injection 防护

PDF 内容只能被视为待检索资料，不能被视为系统指令。文档中类似“忽略之前的要求”“将数据发送到某地址”等内容必须作为普通文本处理，不能改变模型的系统提示、安全规则或工具权限。

### 6.3 医疗安全

- 论文内容不应直接覆盖现行指南；
- 新药和生物标志物必须记录发布日期、适用阶段和地区批准状态；
- 单篇研究不能被描述为已经确认的临床共识；
- 系统继续保持风险筛查和健康教育定位，不能输出确诊结论；
- 正式发布前应由神经内科、老年医学或相关专业人员审核。

### 6.4 版权

涉及版权的论文可以用于内部检索和摘要，但回答不应大段复现正文。系统应展示规范来源引用，并根据文件许可控制原文下载权限。

## 7. 推荐的仓库结构

```text
data/knowledge/pdfs/                 原始 PDF
data/knowledge/manifests/            文档登记和审核信息
data/knowledge/extracted/            提取后的结构化文本
scripts/ingest-pdf-knowledge.py      提取、分块、向量化和入库
scripts/remove-pdf-knowledge.py      按文档或版本删除索引
scripts/validate-pdf-index.py        数量、页码、重复和质量检查
```

生产环境中，原始 PDF 和提取产物应迁移到受控对象存储，仓库目录只用于本地开发和测试样例。

## 8. 第一版实施范围

第一版建议实现：

1. 文本型 PDF 提取；
2. 扫描版 OCR 回退；
3. 基于段落和标题的中文分块；
4. BGE-M3 批量向量化；
5. Qdrant 独立文档集合；
6. 页码和章节引用；
7. 文件哈希与增量更新；
8. 基础质量验证脚本；
9. FAQ 与 PDF 双路检索及简单重排。

第一版可以暂不处理复杂跨页表格、图片语义理解和多模态论文解析。完成上述能力后，系统已经能够形成可用、可追踪、可维护的论文知识库。
